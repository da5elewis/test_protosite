Building a site with Protogen

This site was built using the Protogen 101 series of training, but using some different prompts to generate a site that could be useful for me and for the CX team as a whole. The first round required copying and editing html pages to make changes. I requested an admin page to do this. After some debugging, I was able to create a new page using this admin form. The admin form allows the export, editing, and deleting of existing experiments. I'll test that next.

Context & Goal

Slalom has a new offering we've dubbed Fast Forward, enabled by a rapid prototyping method we're calling Protogen. As part of the Protogen training, I'm building this site, and making iterative changes to it to get familiar with the stack that underpins Protogen. To step a bit away from the prompts offered in the training and move from just copying to experimenting, I've varied the prompts to generate a site that could be useful for me and for the CX team as a whole.

What We Tried

The initial output was very basic, requiring copying and editing html pages that were generated from the first round of prompting. To replace this basic and very manual approach, I requested the creation of an admin page. That didn't work at first and required debugging (aka telling the agent how it was broken and watching it figure it out). This resulted in partial functionality, but only updated summary tiles. I requested another admin screen to generate the detail page and link it to the summary. There are still improvements to be made, but I may proceed with them after doing some additional training...

Results

This is a very iterative process. Things either don't work as expected, partially work, or break entirely. To continue improving the experience you just need to tell the VS Code agent what's broken, or what you want changed. It's actually fun watching the agent's chain of thought as it is working through the problem or request.

Takeaway
Iteration is key

Generating a site experience this way involves a combination of clear strategic and creative direction, and iteration to continually improve on the result. It's the traditional approach (define, design, develop, and 'measure' against your desired outcomes) but compressed.
